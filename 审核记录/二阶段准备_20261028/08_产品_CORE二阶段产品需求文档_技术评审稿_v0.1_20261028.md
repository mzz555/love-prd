### 需求优先级：采用产品提供的三档定义

| 等级 | 名称 | 定义与执行 |
|---|---|---|
| **P0** | **必须实现｜本阶段交付底线** | 不完成则本阶段不能通过验收，或不能进入依赖该能力的下一阶段。技术必须实现，或提出替代方案由产品正式裁决。 |
| **P1** | **优先实现｜允许延期** | 对产品质量、体验或后续开发有明显帮助，但缺失不影响本阶段核心目标。P0 完成且资源允许时优先实现；可延期而不阻塞本阶段验收。 |
| **P2** | **暂缓实现｜后续重新评估** | 本阶段不投入开发，仅保留需求及背景。是否实施、何时实施、如何实施，等待后续阶段或真实用户反馈决定。 |

优先级与完成状态分开：**P0 不等于尚未实现；P1 不等于已取消；P2 不等于业务原则失效。** 沿用能力优先复用，文档约束/背景说明不各自变成一个新模块。本文分级是“需求优先级”；J014、B10 中的 **P1—P4 是引擎缺口队列层级**，两者不能互换，不能按本文 P1“允许延期”去停用本人体验缺口。

### 二阶段要完成什么

**S2-01-04｜P0。** 形成以下本阶段 **P0 增量**，已有部分复用而不重做：

1. 按 CSI32 → 本人追问 → PRI16 → 本人追问 → ECR-RS 伴侣版九题 → 本人追问，组织独立采集。
2. 用审核后的固定题、封闭模板和本人资料完成首次追问；每人三段合计最多 12 轮，保留跳过、记不清、无事件与提前结束。
3. 将回答自动整理为可回指原文、可核验的结构化候选，再按确定性规则形成 A、B、内部三种权限视角的模型雏形、覆盖、缺口及交付程度。
4. 分别验证题目理解、自动抽取忠实性、语义判断与规则执行，说明哪些内容可用、哪些不足或待审核。

**S2-01-05｜P0。** 优先确保清楚本人体验、角色归属和有依据的事件/情境比较；没有合格依据时保留未知，不要求每对达到有限/完整，也不为了证明价值拼出关系模式。采用 J014 已定体验缺口与 B10 目的/预算，不能以研究优先级擅自改全局缺口排序。

## 03 数据输入与整体业务流程

### 输入与内容版本

**S2-03-01｜P0。** 每位输入独立归属本人，A/B 固定，不代表性别或责任。最低原答、状态、窗口、主补、版本与权限信息按下表保留。纯合成开发不等待真人材料；当使用真人资料时，分别完成适用模式的成年、自愿、用途与实际处理告知同意，退出/撤回/安全控制优先；按 B08 核实实际保管、外发及停用清理，不能直接套阶段一期限或以内部人员身份免除。

| 输入 | 必须能核对的内容 | 不允许的处理 |
|---|---|---|
| 量表 | 人、题库及计分键版本、题号、原始选项、实际状态 | 补填空题、混用版本、静默修正题干 |
| 开放回答 | 人、题本版本、段落、固定/自适应槽位、实际模板、原文及作答状态 | 以模型改写覆盖原答；将猜测写成另一方报告 |
| 日期 | 本人主答绑定、具体日/周/记不清、提示窗口与本人时间的区别 | 用共同窗口、伴侣日期或系统提示补造锚点 |
| 自适应来源 | 唯一本人目标、一个请求目的、触发依据、模板及可用线索 | 直接传完整双人模型或一般 A/B 可问包 |
| 权限与控制 | 主答和补答关系、保密与更严限制、拒答目的、修订撤回、停止状态 | 新增题号或新回答行重置原限制 |

以上是业务信息要求，不是已经冻结的字段名或新增 schema 枚举。正式导出、接口与旧九表兼容方案见 09 号 G05、B04。

**S2-03-02｜P0。** B01 使用已冻结来源：CSI32/PRI16 沿阶段一 D4；ECR-RS 九题、中文修正栏、1—7 量尺与计分方案已交付，不再列“尚未选定/须重做翻译”。技术核对实际题序、页面显示和计分配置，缺失指导语不补造，CSI C19 历史改写保留测量解释限制，不据此证明真实自我变化。ECR 以 ECRRS9_C01—C09 的技术 ID 对照原件顺序；命名不是新量表或新产品规则。
