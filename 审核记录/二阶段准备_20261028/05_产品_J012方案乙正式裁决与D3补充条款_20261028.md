## 1. 依据及判断理由

依据 [04 号补充裁决](04_产品_三项补充裁决与判断理由_20261028.md)第 4 节（`love-prd@4b9e1b53e463597a36bfe14714600f6a6daeec9d`）与[技术对 J010—J012 的回复](https://github.com/mzz555/love-prd/pull/1#issuecomment-6465494626)第 2.1—2.4 节，产品负责人明确要求同意技术推荐，并开始题本设计。

产品接受技术澄清：保密回答目前已在讲述人本人视角中参与关系分析，包括与伴侣可共享材料形成的关系判断，并非完全没有使用。尚未开放的是伴侣视角，以及团队内部视角中的跨人使用。

本轮选择乙，理由为：

1. 保留用户“不让 TA 知道”的承诺。既不展示回答，也不让它通过结论、追问或许可清单间接改变伴侣看到的内容。
2. 满足“不展示不等于不分析”的产品要求。本人视角照常使用；团队受控内部也能够研究保密回答参与后的关系结构、配对、比较和共同过程。
3. 不改 D0 V1.1 的对方隔离条款。原 05-02 限制的是对方结果，乙只调整受控团队内部的分析能力。
4. 不扩大本轮交互与研究负担。继续不设保密理解专项测试，不新增保密解释页；引擎改动与测试留到题本试答修订、技术最终审查后一起排期。

甲保留内部分析限制；丙会让伴侣看到的结果受保密材料影响，与不让伴侣知道的承诺存在张力。产品本轮均不选择。

## 2. 最终裁决

**采纳技术推荐的乙方案，登记为 J013，细化并修改 J012 的实现范围。**

- 本人视角：保密回答继续参与全部合法分析，包括关系判断。
- 团队内部视角：允许将仅受 `private_request` 限制、且通过其他有效性检查的材料作为跨人依据；内部结果仍只供有权限的团队复核和研究。
- 伴侣视角：不加入这条保密回答及其派生依据；伴侣的预览、结论、可问包、提问顺序、数量与许可清单不因它改变。
- 高敏感、可识别第三方、未判清、无效来源、安全控制等限制继续生效。多标记取最严，不能将“有保密标记”当作解除其他限制的理由。
- 许可与“双方材料句”的计算保留原来的隔离口径，不能直接改用放开后的团队内部分析结果。
- 内部交付档位仍取 A、B 用户视角中较低的一档，不因内部新增对象而提高用户可交付程度。
- 不新增保密理解专项测试；不扩大资料公开、外部工具或访问人员范围。

对同一份输入，乙与现行方案相比，A、B 用户结果都不变；只增加受控团队内部可分析的关系对象。这不意味着 A 更改自己的保密回答时，A 本人的结果不能变化。

## 3. D3 第 7 页的正式产品补充条款

本节作为 [D3 技术执行手册](../../参考资料/CORE_阶段一技术执行手册_.pdf) v1.1-R1 第 7 页“按查看者隔离材料和预览”的产品修订补充，与原件一并阅读。原 PDF 保留原字节与历史版本；本节明确替代其关于内部视角不得用保密资料形成共同模型的限制。其他章节不因本节自动改写。D0 05-02、05-03a、05-09c 不变。

替代原句“internal 是受控诊断，不是可以任意使用私密资料的共同模型”的条款为：

> internal 是只供授权团队复核与研究的受控分析视角。在其他来源有效性与资料类别限制均满足时，private_request 材料可以在该内部视角参与跨人关系分析；这不授予任一用户读取对方保密材料或其派生结果的权限。A/B 输出、可问包和许可计算必须使用各自独立的隔离投影，不得回退或借用放开后的内部结果。

本次修订的精确范围如下：

| 项目 | 乙方案的要求 |
|---|---|
| 仅有保密限制的有效材料 | 内部可作配对、命题、实质比较与共同过程等跨人依据 |
| 同时带高敏感或可识别第三方限制 | 不得因内部放开保密而获得跨人资格 |
| 待复核、无效引用、失效依赖 | 沿用原隔离，不因本次决定自动变成有效 |
| 用户视角的内容与选择依据 | 继续按各自权限计算，不从 internal 补取 |
| 许可清单、绑定、双方材料句 | 独立保留原先排除私密、高敏、第三方材料的计算口径 |
| 内部输出的读取 | 限原有受控复核与研究范围，并标明新口径版本 |

这是一项已经作出的产品要求修订；不代表 D3 原 PDF 已重排出整版，也不代表 SPEC、代码和历史运行结果已更新。实施时由技术同步具体规则版本、输出说明与验收记录。

## 4. 适用公式与不变量

以下公式用于准确表达乙方案，不是新增评分或关系分数。

设：

- `S_A`：A 本人资料中可在本人范围使用的部分，包含其保密回答；
- `R_B→A`：B 的资料中按既定产品权限可供 A 使用的部分；
- `I_甲`：现行团队内部分析投影；
- `ΔP`：仅因为 private_request 而在内部被限制为本人范围、其他检查均合格的材料；
- `F`：沿用既有来源、证据及关系规则的分析过程；
- `U_X`：用户 X 的完整合法结果集合，包括预览、交付程度、可问包与许可相关输出。

**可用范围：**

```text
本人视角的关系分析 = F(S_A, R_B→A)
乙方案内部分析输入 = I_甲 + 将 ΔP 的内部资格由“本人范围”调整为“可作跨人依据”
乙方案伴侣视角中的该保密回答影响 = 0
```

“调整资格”仍受高敏感、第三方、待复核、来源和安全等更严格限制约束，不是无条件追加全部材料。

**同一输入、不同方案的不变量：**

```text
U_A^乙(D) = U_A^甲(D)
U_B^乙(D) = U_B^甲(D)
许可计算投影^乙(D) = 许可计算投影^甲(D)
内部交付档位^乙(D) = lower(用户档位_A(D), 用户档位_B(D))
```

**保密内容变更的不变量：**

当 D 与 D′ 仅在 A 的保密回答及其派生材料的有无、文字上有差异，其他可释放材料与必要控制保持一致时：

```text
预览_B(D) = 预览_B(D′)
可问包_B(D) = 可问包_B(D′)
许可清单_B(D) = 许可清单_B(D′)
```

上述 B 输出要求逐字节一致；交换 A、B 后同样成立。安全暂停、退出、撤回同意等必要控制变更按各自规则另测，不能为追求字节不变而忽略停止控制。

**首次追问的额外约束：** D1 Q02 规定首次追问只用本人资料。因此题本选题比一般用户视角还要窄：即使 B 的资料可共享，也不进入 A 的首次选题。乙方案内部结果不能反馈首次追问题目、顺序、数量或结束理由。
