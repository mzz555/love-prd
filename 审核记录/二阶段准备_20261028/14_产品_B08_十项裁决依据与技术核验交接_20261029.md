## 1. R01｜人工题意试答与实时自动追问分开准入——方案 A

**原稿问题**：B08 第 1—3 节同时写了“仅题意试答”和“实时自动追问”，若混在同一份泛化告知中，可能将人工试答的同意误认为已经允许把回答发送给千问，也可能让尚未完成的在线工程不必要地拖住题本试答。

**判断理由**：B10 的人工试答是验证题目可理解度、实际回答质量和模拟追问；J017 真人在线试点才验证“本人回答→千问自动抽取→本人的下一题”。两种实验目的、工具和风险不同，同意必须与实际处理范围一致；前一种结果不能冒充后一种效果或安全验收。

**最终裁决**：
1. 保留**模式 M1：人工题意试答**，仅在实际做到无外部 AI 处理时适用；可由授权人员按题本或人工模拟追问，施测实际题目范围须写实，不必声称完整 57 题都测。
2. 保留**模式 M2：实时自动追问**，包括作答中途向实际核实的千问 API 发送必要本人资料；启用前需相应明确同意及技术/服务核对。
3. 两模式分别告知、分别留存选择，跨模式、试后上传或增加外部用途均先核适用条件并取得相应同意；不得拿 M1 同意“补签”M2。是否提供结果试读、费用补偿、退出后补偿、题目范围均按批次填实。
4. M1 满足该模式相应真实告知、保存访问、撤回及安全安排后可独立准备，不等待 M2 全部接入；**M2 未满足 B08，不使用真人运行**。两者均须先落实适用个人信息保护要求。
5. 本轮不新增额外保密理解专项测试，不扩展 B10 既定的人工题本研究范围。

**技术/产品待核**：批次和实际模式、参与人数、真实题目/试读范围、费用与补偿方式、是否有线下或远程主持、人工试答会不会使用其他数字化工具。

## 2. R02｜处理主体、联络和分工——方案 A

**原稿问题**：第 2、5 页暂写“【组织及个人信息处理主体全称】、负责人、联系人、访问人员”等；产品负责、技术拥有系统权限，不等于可以不区分法定主体和具体执行人员。

**判断理由**：参与者需要找到实际承担个人信息处理责任的主体与可用的个人请求入口。研究回答既含亲密关系信息又可能含他人信息；三名创始成员关系亲近不等于三个人都能默认读取所有资料。若对外说有访问隔离，必须与技术现状相符。

**最终裁决**：
1. **优先按实际决定处理目的/方式的 CORE 已注册公司作为个人信息处理者核定**，但必须查公司全称、实际账号/合同及控制关系；若真实运营主体不符，须按实际核订，不能凭公司已注册就假定事实。
2. 产品负责人组织试点、本人私密联络、受理更正/撤回/删除和管理职责；龚老师访问其语义核验所需资料；技术访问配置、运行、故障定位、接口、清理所需资料。各人具体访问人、替补和限制待填。
3. 参与者联系方式与参与编号的身份映射和研究回答**分开保管与授权**；原则上不向仅做语义判读者开放身份映射，不向普通技术排障无条件开放全部正文。为真实故障必须有限查看正文时记录原因、范围、人员和留痕。
4. 设置实际可用的**本人私密渠道**，至少处理咨询、查阅、更正、收紧权限、撤回、退出、删除；伴侣不得代为同意或批准；私密联系不得经二人共用群聊，且安全场景须核联系渠道是否安全。
5. 依实际人员关系及合同核对公司内部授权还是委托/其他对外提供；不在公告中虚构法定专项负责人、现成权限系统或不存在的固定时限。

**待核**：公司法定全称、真实处理关系、通讯渠道、受理与替补、回复计划、实际权限/访问日志及人手、工作副本托管位置；没有查证前一律【待核】。

## 3. R03｜千问 API 实际处理与外发最小化——方案 A

**原稿问题**：第 3、6 页正确写到千问实时处理、请求和返回留档，却尚未填写实际账号签约主体、模型、端点、地域、字段、服务侧留存/删除。仅说“阿里云千问”不足以向参与者准确说明外发及处理。

**判断理由**：J017 的核心是在线选本人下一题，不需要发送对方资料或整份双人模型；但使用自由文本可能包含身份或敏感信息，必须核发出前的实际限制。阿里云公开隐私说明表示调用数据会存储且不用于模型训练；**不等于零留存**，也不能将国际站政策套用国内账号。

**最终裁决**：
1. 在线外发仅为此次已告知且合格的**本人必要回答、最少必要上下文及选题信息**，不发送伴侣回答、完整双人材料、真实联系资料、身份映射、与选题无关的历史资料；提前核自由文本中的未授权敏感或第三方信息如何阻断/限制。首次本人投影独立于 A/B/internal 投影。
2. 只有相应模式的有效同意及实际适用法律/权限满足时才调用；“不要让 TA 知道”**本身不禁**在额外同意有效且其他限制通过时发千问，但不能绕开高敏感、第三方、待核、停用等更严约束。
3. 业务必要的调用/返回/选题记录仅在受控权限和核定期限内供复核；**CORE 自有存储**与**千问服务侧留存/删除**分别核对、分别披露，不能写“已删 CORE 就等于服务商全部删除”。
4. 具体服务合同主体、实际账号/业务空间、固定模型 ID、调用接口、国内外地域、真实发送字段、服务侧保存/删除及第三方模型协议由技术提供证据，产品据实写告知；若另接其他模型/地域则重核。
5. 未核明有效同意/接口/处理限制/留存能力及相关法律要求前，M2 真人路径**不准运行**，但不妨碍合成 API 模拟与适用工程开发。

**待核**：服务签约和实际处理主体、实际模型而非探索代号、接口与云地域、服务侧删除能力、日志正文与位置、API 密钥保护、异常请求/排队任务阻断；不要将客户资料存入公开仓库。

## 4. R04｜“不要让 TA 知道”准确告知，不新增理解测试——方案 A

**原稿问题**：第 3 页已有 J013 的基本含义，但普通参与者可能把“保密”误当成“CORE 连本人分析/团队内部研究也不使用”；同时绝对不变承诺易掩盖安全暂停/退出这类必要停止控制。

**判断理由**：此前 J013 乙方案已明确本人视角合法使用、受控 internal 增加合法跨人研究、伴侣结果及派生对象受隔离。用户真正关心保密能否做到，而不是被安排额外考核或劝其公开。告知要说清**对象、用途和撤回的差异**。

**最终裁决**：
1. 对外明确：“不把这条回答给 TA 看，也不利用其派生依据生成或改变 TA 可见的普通关系分析、预览、可问包、顺序、数量、许可”。本人合法分析及授权团队**本次已告知的**受控内部研究仍可用。
2. M2 中有符合条件的额外千问处理选择及其他限制许可时，私密回答也可能最小必要外发；不是交给 TA；不可将本项选择替代外部模型处理同意。
3. “希望连后续研究也不用”通过本人私密渠道提出撤回/删除请求；先停用再按 R06 处理，已完成的合法处理不等于能物理撤销。
4. 更严格的敏感、第三方、未判清和安全规则优先；安全暂停、退出、撤回同意这类必要控制按自身规则执行，向伴侣仅中性停止、不泄露原因。
5. **不新增保密理解专项测试、专项页面、访谈或劝改保密的流程**；正常试答可自然观察文字是否被误解。

**待核**：系统是否能证实伴侣结果、选题、数量、许可乃至间接痕迹不受 A 私密材料变化影响；技术证据见 16 号 B08-A04—A06。

## 5. R05｜用途最小化：允许本轮规则改进，不授权训练/公开营销——方案 A

**原稿问题**：第 1、3、6 页禁止训练、营销、录制及随意转外部工具，方向正确，但“模型训练”易与“根据试答发现错误并修改提示词”混淆。

**判断理由**：本轮真实目标是核题意、追问合适度、抽取是否忠实、规则怎样改；与把可识别私人回答长久收集为微调集、在社交平台晒案例是不同用途。真实人物经历替换昵称后仍可能可识别。

**最终裁决**：
1. 允许在已告知范围内由获准人员为**本轮研究**使用必要回答、核验错误、复盘错误并修改题本、提示词、判断/技术规则；优先保存抽象问题总结而非永久保存原文。
2. **本轮不授予**真人回答模型微调、持续训练、永久语料库、公开案例、可识别截图、广告营销或商业素材使用权限；以后有新用途先核法律条件并依法取得所需授权。
3. 未在本轮告知及技术/权限清单的 Claude、ChatGPT、在线表格、其他云端 AI 和音频转写服务**不得复制/发送真人资料**；旧试点工具批准不能自动扩展本批次。纯合成数据工具使用另论。
4. 默认不录音、录像、录屏；若确实使用语音输入/识别、音视频录制、转写或第三方工具，需先核必要性、服务路径和相应告知同意，不得用“没有留录音文件”遮盖音频外发。
5. 阿里云公开“不用于训练”的说明不等于“不会存储”；实际服务/第三方模型及协议按 R03 核。

**待核**：实际研究和调试工具白名单、是否录制/语音转写、受控工作平台、是否存在默认自动上传或同步、已注册服务账号的合同/权限。

## 6. R06｜分类限期保存、撤回先停用、删除可核对——方案 A

**原稿问题**：第 7—8 页全面列出原始资料、派生、联系映射、请求/返回、工作副本、备份和服务侧，但统一【待填】；“测试完成后删除”无法确定起算点与责任，也无法证明不会恢复失效资料。

**判断理由**：CORE 当前是小规模短期研究，不应长期囤积亲密信息；原始回答、访问映射、后台日志、依法需保留的最小合规处理记录和云服务侧各有不同作用及控制能力。法律要求最短必要，并非统一规定“全部 90 天”；撤回前已合法处理不当然逆转，撤回后无须等物理备份完全清理才停止普通使用。

**最终裁决**：
1. **分类**制定具体起算日、到期日或可计算时长、责任人、存储路径、例外依据；目的已完成时可提前清理，不把上限当最低保存时间。
2. 产品同意将**原始/派生回答在本人完成本轮后最迟不超过 60 个自然日**、人工临时副本在工作完成后**建议 7 个自然日内**（且不晚于原始资料期限）、可恢复备份在活动数据删除后**建议 30 个自然日内**清理作为**待技术与实际合规核实的期限提案**。这些不是法定期限，不是已获技术保证，更不是已可向参与者承诺；若安全、备份或业务事实做不到，必须**真人前**由技术给出真实方案、产品审定并修订对外文字。
3. 含正文的请求/返回/人工工作副本按更短必要原则，不自动借“研究复盘”长期保留；身份映射仅保留联系及办理合法请求所必需时段，控制与原始资料分离；单独留存必要的同意/撤回/删除/PIPIA 记录按适用法律时限，**不因此保存整套原始问卷多年**。
4. 退出、撤回、权限收紧、更正时，**首先阻断新的普通分析、外部调用和可取消的队列任务**；随后停用并核旧引文、主补、标签、配对、预览、假设、许可、缓存、人工副本、备份及已发送云服务侧数据；只能保留独立合法支持的内容。
5. 分别记录“已停止使用／工作副本已清理／备份待清除／外部服务侧待核或依法依约留存／最少法定记录保留”；不得用“完成删除”替代实际状态或承诺收回他人已获知的内容。无法立即删除的受限资料不得继续用于普通研究，恢复备份不得把停用资料重新激活。
6. 用户请求通过真实私密渠道办理，受理确认、工作副本清理、备份及服务侧时限由产品/技术同口径核实后写给参与者；**不引用阶段一暂定 90 天、3 工作日、30 天等为事实**。

**待核**：数据库、对象存储、日志、缓存、备份与可恢复机制、云服务侧响应能力、具体期限、执行责任与回执、是否有法规要求长期保留的特定记录。

## 7. R07｜可信当前风险暂停＋非原标注者复核，不冒充危机服务——方案 A

**原稿问题**：第 8 页规定安全暂停和私密联系，但“可信当前安全信号”容易被误判为一切不愉快关系事件，也可能因技术重跑自动解除。

**判断理由**：普通争吵/拒答不等于当前危险；真实的人身威胁不能继续当一般关系纠纷追问。CORE 是三人研究团队，不能诚实承诺全天值守、诊断或紧急救援。伴侣也可能接触参与者通讯，贸然外呼或发敏感短信反而产生风险。

**最终裁决**：
1. **普通争吵、低满意、一般负面情绪、拒答、双方说法不一致**本身不触发安全暂停；过去经历按实际情境和敏感信息规则处理，不自动等同正在发生的人身危险。
2. 有**明确可信当前或即将发生的人身伤害风险**等信号时，暂停相应普通分析及追问、隔离最少必要资料，转受控人工核查；模型不能凭情绪词直接诊断/宣称危险，也不为查证风险逼迫用户回答。
3. 由**非原标注者且已授权**人员复核，产品负责组织、选择确有必要且安全的本人私密联系，技术执行隔离/阻断与状态记录；如团队能力不足，提供适当专业求助指引，不冒充合格危机干预机构。
4. **不得向伴侣求证、泄露原话、泄露谁触发、派生原因或秘密状态**。双方必要时只收到中性停止提示。对本人联系须先考虑渠道是否安全；不是所有个案都自动外呼，真实紧急义务另依法核。
5. 已经触发的安全暂停不得仅因更正、重跑、撤回、删标签自动解除；按既有受控复核重新决定。真实安全案例不进入普通公开测试；用合成案例验证。
6. 对外清楚说明：可以随时停止、跳过；本轮**无全天候监测、实时人工值守、临床诊断或紧急救助承诺**。

**待核**：受控安全复核人及替补、报告通路、隔离开关和恢复资格、可用的中性文案、安全联系渠道、是否出现无法承担的紧急处理情境。

## 8. R08｜法律敏感类别、服务处理关系、PIPIA、跨境按实际核——方案 A

**原稿问题**：第 9 页提供按需单独告知模板，但可能在自由文本中意外出现医疗、创伤、健康、第三方等信息；“用户主动写了”不等于有权整段外发。产品里的保密/高敏标记不等于法律上的敏感个人信息定义。

**判断理由**：CORE 的目标是关系体验，不是采集全部私人生活。敏感个人信息有特定目的、充分必要与严格保护要求；实际委托处理、向独立处理者提供和跨境流转有不同法律条件，不能单凭“是千问 API”判定。规模小不自动免除适用的事前影响评估义务。

**最终裁决**：
1. 默认**不主动索取无关敏感细节和第三方可识别信息**。依具体资料、泄露风险和法律定义识别是否属于敏感个人信息；个人的“不要让 TA 知道”不等于法律敏感分类，也不是扩大用途的通行证。
2. 对自由文本主动出现的未获准敏感/第三方信息，核**进入外部调用前**的处理能力及可行限制；未经必要依据的路径不得普通跨人使用/实时外发，技术无法保障即不启动对应真人路径；不因人工阅读就天然合法。
3. 确有必要处理某个特定敏感类别时，先确定具体目的、充分必要、具体风险和保护措施，按适用要求进行专项告知及单独同意；**不让参与者一次性勾选“同意处理所有敏感资料”**，不要求其替无关第三方作概括授权。
4. 技术按实际账号合同判断千问是否为受托处理、独立个人信息处理者、第三方模型及转委托；合同/监督/其他告知同意按适用关系办理。依真实端点、推理/存储与其他接收路径判断跨境，**仅接入 URL 不足以证明整个数据路径**。
5. 产品组织必要的个人信息保护影响评估及处理记录，技术提供真实数据路径、必要性和安全措施；法律适用情形由具备资格人员按实际事实判断，**不能把本 B08 文字当成已完成 PIPIA**。法律要求保存的评估和处理记录独立按法定期限处理。
6. 确认“确无此类处理”可标**不适用**，不额外制造一份空白的敏感同意或虚构跨境路径；必要的真人处理前，实际满足的法定要求先落实。

**待核**：实际敏感类别和是否必要、实时外发前控制与误判处理、合同与数据地域、接收/委托/转委托关系、是否应单独同意及具体 PIPIA 记录、法律专业复核意见。

## 9. R09｜用合成资料验证同意/外发/隔离/停用/删除——方案 A

**原稿问题**：第 10 页只写“合成验证”而缺可验收的正反例；仅检查页面最终没有显示，也无法证明请求没有违规发出；完全空输出的对照可能造成隐私测试假阳性。

**判断理由**：J013/J017 已有 A03—A05、A13、A22、A23 等有效基础，可以共用。B08 应针对**真人数据的准入安全门禁**补上独立具体测试，不重新验全套量表/关系模型。应先确定预期，实际查看外发/排队/许可/恢复路径，不照程序结果回填预期。

**最终裁决**：
1. 固定**B08-A01—A10 十组核心合成用例**；输入与预期先行，有正反例，检查缺少和多出项；可继承 09 号 A03/A04/A05/A13/A22/A23 规则但实际回放证据不能以“继承”代替。
2. **A01—A03**：未同意/无效同意不发送、仅 M1 不发送、M2 同意后撤回则停止新请求及可取消任务，并追踪已发送服务侧状态；以模拟 API 拦截/调用次数及审计日志证明，而不是只看 UI。
3. **A04—A06**：A 私密回答有无/变文不影响 B 合法普通结果/许可，A/B 对称；B 全资料替换不改变 A 首次本人选题；多标记最严格优先。包含一条合法内容确实可以变化的非空对照。
4. **A07—A08**：更正/撤回后主补、标签、配对、假设、预览及许可依赖失效；退出后一方来源不再支持另一方关系结论；日志、副本、缓存、备份、服务侧状态分别留痕，不能凭模拟测试宣称云服务已完全删除。
5. **A09—A10**：真实当前安全线索合成触发暂停，重跑不自行恢复，不把普通争吵误判为危机；模型异常超时/非法安全降级，不能绕开同意或安全门禁，不把技术故障误记为用户无信息。
6. 测试记录至少写合成输入标识、独立预期与来源、规则/提示词/接口版本、运行方式、外发请求审计/权限变化、实际结果、差异归因、测试人、日期和结论（通过/失败/未执行/阻塞）。模拟 API 可验证本机门禁，不等于真实云端留存与删除验证；技术仍需完成实际合同和运行路径核对。
7. B08 只验准入安全关键路径，不绑架全部二阶段算法验收，也不要求先用真人“补测”异常用例。

**完整测试设计与回执字段**：[16 号](16_产品_B08_资料处理事实核对与真人准入验收清单_20261029.md)第 3 节。

## 10. R10｜文档版本、分别确认与分模式准入——方案 A

**原稿问题**：第 4、10 页分别同意及实际记录结构可用，但所有人名、时间、版本、合同及处理事实未回填时，无法判断用户究竟同意了什么；仅完成产品草稿也不代表技术已具备保护能力。

**判断理由**：法律上的充分知情、独立选择依赖具体版本和真实处理事实；A 邀请 B 不等于 B 同意。人工 M1 与千问 M2 应按实际处理路径各自准入，防止单份概括同意绑架其他用途；同意可以用符合法律及证据要求的电子记录，不一律要求纸张。

**最终裁决**：
1. 产品审核结束后，**分别形成可填实的 M1/M2 告知与同意稿**（15 号），两者共用准确的基础说明，M2 另显著列明中途实时发千问、请求/返回、服务/地域/留存及真实选择；实际涉及敏感类别时另附专项告知与单独确认。告知版本/批次/处理主体/联系与期限未核实前只作为**待核模板**保存，禁止给真人签署未填版本。
2. 每位成年人**独立**取得适用版本、明确选择同意/不同意，不预勾，保留可核验的本人选择、参与编号、批次、时间、适用范围、告知副本和撤回状态；**不拿伴侣签名代签，不把点击继续或邀请成功默认为同意**。
3. 同意资料私密保存，不放公开仓库；告知方式与实际系统权限必须一致。需要法定单独/书面同意时另按实际办理；不让普通研究同意遮盖敏感处理或对外提供的新要求。
4. **模式分别放行**：M1 满足其无外部 AI 的真实执行安排、有效同意、保管/访问/撤回与安全要求，可以独立开展；M2 还须满足真实千问合同/字段/地域/外发前安全、必要法律条件、相应同意、R09 测试及处理期限，才可准入。任何必要条件失败，禁止该模式真人运行；不因此中止合法的纯合成与技术开发。
5. 文件交付按三层区分：①产品规则审核已完成；②事实核对及技术准入尚需逐项签核；③每一位真人的实际同意需真实取得。**任何一项不得代替其他两项**。
6. 项目时间限制沿 J020：30 分钟是主动作答设计目标；32/38/45 按“主动用时＋系统等待”且仅扣暂停；45 分钟不再发新题，但当前题可提交，不保证 45 分钟内一定结束；模式 M1 若仅部分题本试答，不误称全流程。

**待核**：版本号、批次、处理主体、真实联系/权利办理期限、实际人员/工具、题目范围、费用补偿、结果试读、服务处理、保存删除、专项资料、各测试证据、真正的同意记录及实际开放日期。
