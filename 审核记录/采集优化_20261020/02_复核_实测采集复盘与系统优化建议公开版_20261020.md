# CORE 实测采集复盘与系统优化建议公开版

2026年10月20日　产品侧已同意　待技术审核确定　公开版

## 一 核心判断

建议先优化采集机制和固定问卷，再招募下一批目标用户。当前问题同时涉及参与动机、页面防漏、题目理解、信息结构和双方资料的可比较性。只更换招募对象，仍可能收不到规则所需的信息。

这批资料保留为真实流程及边界测试样本。它们对“资料不足不编结论、来源撤回、保密、退出和隐私过滤”有价值；不能据此证明真实双人比较已有效，也不能据此判断 CORE 没有产品价值。

### 已取得的证据

- 技术反馈显示，问卷导出、人工标注和模型运行能够衔接，P2、P3、P4 合计1,009条预期一致；审核还发现并修正了引擎侧规则细节。
- 三对都未形成可共同交付的内容。真实资料上的共同事件确认、双来源实质比较及重复过程，仍缺少足够覆盖。
- 目前有证据支持“数据稀薄、局部漏答、词义不清和问卷引导不足”；“朋友帮忙导致敷衍”来自本次招募与观察背景，不能由三对数据单独证明全部因果。

### 优先处理

1. 修复或验收整页漏答提醒、未完成状态和导出归位，防止“点到结束”被误当成“数据齐备”。
2. 将关键开放题改成简短主问加可选的固定补充提示，先解决经过、期待条件和自我变化要素缺失。
3. 为双方独立收集更清楚的事件定位线索，增加共同固定情境下的期待比较；不转发对方回答来制造一致。
4. 清楚说明数据用途、伴侣可见范围、跳过及撤回方式，核查全保密选择的实际理解。
5. 先做小规模可用性试采，再招募目标用户；将自然采集与定向规则覆盖分别记录。

### 本次建议的边界

产品罗林海已同意C01至C12优化建议，授权将建议与文档交技术进一步审核确定。本文保留优化建议及依据；实施范围、问卷语义、版本映射、工作量及试采安排均待技术回复确认。本次不修改D0、D2、冻结题库、实际问卷或原始数据，不启动招募。公开版不含参与者回答、逐人记录或真实工作簿；明细沿用受控渠道。



## 二 数据核查的结论与适用范围

本轮复盘对象为P2、P3、P4。P1仅作另一个中途停止的过程案例，不并入三对回放结果。小规模便利招募不能支持总体完成率、目标用户成功率或产品价值的普遍结论。

| 核查方向 | 本轮审核结论 | 对优化的影响 |
|---|---|---|
| 量表完整性 | 历史页面存在未选择仍提交的情况；技术已核实不是本次导出丢数 | 优先验收漏答提醒及显式略过 |
| 开放题内容 | 具体行为、期待条件与变化要素未稳定取得 | 改善题目结构，不以字数替代语义 |
| 事件对应 | 共同事件确认及双来源实质比较覆盖不足 | 独立收集定位线索，并比较共同固定情境下的期待 |
| 权限与控制 | 已验证保密、撤回、退出及资料不足处理的适用分支 | 保留规则，核查参与者对设置的理解 |
| 研究适用性 | 便利招募与作答独立性存在限制 | 自然采集与定向覆盖分别记录 |

### 已确认与未确认的原因

- 已确认的历史问题包括页面防漏不足、部分开放题主问未直接要求现行规则所需的信息，以及事件定位线索不足。
- 招募来源和参与动机是本轮组织复盘的重要背景，但不能据此单独证明所有资料不足均由敷衍造成。
- 保密、没有事件、记不清及明确暂无变化都可能是真实选择，不应统一当作低质量。
- 实际布局、默认设置是否导致误触，以及提示改版会带来多大改善，仍需手机观察和小规模试采。

公开仓库保留审核结论及方法，不展示逐人缺答、权限分布、答题时间、字符长度或回答内容。完整统计与原始证据由产品经既定受控渠道提供技术核对。

时间短、选择相同、回答短都只能提示核查，不能直接判不认真。研究也建议结合多个质量信号判断。[R7]



## 三 问题证据与原因判断

### E01 整页量表可以未选而继续

技术P1—P3议题第08号回复已查到历史页面提交记录，核实缺项属于未选择而非保存失败或导出丢数。应验收页面防漏和完成状态区分；具体原因仍需观察作答过程。

### E02 具体行为未被稳定取得

R09现有单一主问未稳定收集到可定位的本人具体行为。泛泛表述可是真实回答，却不足以承接行为规则。低投入与题目缺少表达引导可能同时存在。

### E03 题目词义直接影响事件是否存在

R05中“认真聊天”的含义需要澄清；若参与者对事件类别理解不同，同一规则下的有无事件和可比较性也会受到影响。先明确团队要采的交谈类型，再验证理解。

### E04 相似事件名称不能确保事件相同

本批事件对应的可用线索仍不足以确认共同事件。只靠名称或粗时间，不能证明双方指同一次；各自选择最近一次时也可能选到不同事情。应保留待确认状态并改进独立定位。

### E05 需要与变化的主问少于规则要求

R08问具体期待，未明确收集适用条件；R10问有什么变化，未明确收集之前、现在和本人评价。样本中的期待、变化多只有部分要素。它们可是真实有效的回答，但仍不足以达到现行最低信息。

### E06 元视角题不替代本人或伴侣自述

R12采集的是本人对伴侣看法的猜测。含义不明时不能解释成确定特征；在采集预算有限时，其优先级低于本人体验、具体行为及可比较期待。

### E07 保密设置的理解需要核实

核查默认值、选择位置、批量继承及文案理解，也允许设置反映真实顾虑。目前不能将保密选择认定为误触，更不能认为取消保密就能增加合格信息。

### E08 历史配置和溯源增加了人工核查成本

历史窗口配置、按钮归位及中途停止状态曾需要额外核查。已有技术结论或修复安排，应逐项回归验收，不把历史问题全部当作当前仍未修复。

### E09 参与关系和独立性存在限制

本批采用朋友便利招募，帮忙动机与投入程度来自产品组织复盘。作答独立性的限制按已有技术口径保留；时间重叠本身不证明讨论，未报告讨论也不是独立性的外部证明。

### E10 一次问卷难以覆盖重复过程

R02、R05分别只索取一次事件，且事件类型不同。重复过程需要至少两个不同实际事件各有完整共同过程。换一批认真用户也不保证一次问卷自然覆盖；规则验证应另列定向采集计划。



## 四 采集系统的优先优化

### S01 区分漏答与主动略过

下一页发现未处理量表题时，提示还剩几题，并提供“返回填写”和“本次暂不作答”。不预选选项、不替用户填值；确认略过后保留缺项，分数仍按原规则为null。开放题继续保留没有、记不清和不想回答。

提交完成、量表完整和可供分析应分别显示。中途退出、页面未展示、明确跳过、记不清不得在采集记录中混为一类；九表暂不能表达的过程状态先保留在采集日志或受控交接说明，由技术决定映射方案。

### S02 以手机实际操作核查页面

用实际手机检查选项是否被横向滚动、键盘或按钮遮挡，页面下一步是否过于抢眼，返回后答案是否仍在。现有证据未证明具体布局缺陷，因此先观察和复现，再决定缩短每页题数或改单题显示。固定量表题干、选项、顺序与分值保持冻结。

### S03 明确保密和研究用途

解释“仅团队处理”与“模拟伴侣可见”两个范围，说明何时可跳过或撤回。仅展示本人设置，不向伴侣显示隐藏内容、保密数量或关闭原因。核查默认值是否意外覆盖选择；已有明确保密不能被后续切换或补充回答绕开。

历史K03采用默认同意是技术本轮例外口径。本次建议下一批改为双方分别明确确认简短用途说明并能看到联系渠道，作为新裁决，不追认网页上不存在的同意操作。

### S04 让原始记录可以直接解释

验收“最近没有”按钮准确归位、正文不覆盖、日期父题关联和原始版本保存。新采集按北京时间建对冻结E1／E2绝对窗口，双方一致；不倒改P4历史窗口。新增补充内容保留实际来源和提示版本，不由GPT补写成旧回答。

### S05 保留最少够用的过程信息

记录页面进入、提交、未选项数量、保存成功与恢复、主动略过和独立作答自报。主动用时排除后台闲置；保留问卷版本和招募来源。先用小型管理清单即可，无需搭建大型行为平台，也不采集键盘内容或剪贴板。

### S06 加一道采后适用性检查

技术导出前给出格式和缺项摘要；产品、龚老师判断内容适用范围。结构错误先修系统，真实缺答不补造；没有事件、真实无变化、拒答及保密都可以是合法记录。未经同意，不因发现缺口而联系已拒答者补答。

强迫回答的研究结果并不一致，已有实验观察到退出增加及开放题回答缩短。因此建议防无意漏答，同时保留明确略过，而不是要求写够字数才可离开。[R4]



## 五 事件问题如何改得可回答

### Q01 先定义要采的交谈

建议将R05中的“认真聊天”说明为“围绕一件具体事情交换想法、安排或感受的交谈，不要求深入谈心”。是否包含线上交流，以及日常安排能否算入，应由产品先明确，再做认知测试。这是语义调整，不能只当页面润色。

R02继续聚焦普通日常意见不同，不引导严重争执。两题都保留没有事件、记不清、不想回答的入口，不暗示每对都该有冲突。

### Q02 主问之后提供固定的可选提示

先保留用户的自由叙述，再让愿意补充的人按顺序补足少量信息；每一步只问一个内容，不在一屏要求写完故事。候选提示如下，需批准后试用：

1. “这次主要在说哪件事？”用于定位具体情境。
2. “你当时具体说了什么或做了什么？”用于本人行为。
3. “接着你观察到TA怎么回应？”只收观察，不要求猜动机。
4. “后来这件事怎样结束？记不清或还没结束也可以。”用于结果。

可以把第3、4项折叠为可选补充；先用试采决定是否保留。首轮建议整份最多出现3至5条补充提示，用户可随时停止；预算内未收齐的要素照实保留，不能把所有题都展开。与事件关联的本人感受可另问一句，但不能把“我感到怎样”改成“TA让我怎样”。不提供有内容的示范答案，不显示伴侣版本，不让模型替用户补齐。

### Q03 日期和场合提供真实定位

R03、R06可考虑增加本人选择的大概日期、日期范围或场合分类；始终允许记不清。保留精度，不能把一周自动变成某一天。场合与动作分别保留来源，不因为系统窗口相同就算共同线索。

若用户选出窗口外的事件，先说明范围并让其自行确认或保留偏差记录，不静默移动日期。确切日期加场合仍须双方独立提供并符合原确认规则，系统分配的相同事件标签不算两类证据。

### Q04 增加可比较性有两条不同路径

路径一是双方独立描述各自事件，改善细节后再判断能否对应。路径二是在双方都会遇到的同一固定情境中，分别问期待，例如“遇到压力、想向TA倾诉时，你希望TA怎样回应？”这可以比较期待，不能证明真实行为或同一事件。

优先试这两条路径，不采用将一方事件描述自动发给另一方确认的做法。一项107对伴侣的日记研究说明了共享事件定位的难点及另一种可行方法，但该研究会转发事件叙述，与CORE现有独立性及跨人线索限制不同，不能直接照搬。[R5]

固定提示和新增采集字段改变了本轮“九个单一请求、不发送正式追问”的边界。应批准为下一轮固定采集版本；原九表不自行加列、不把多次回答拼成一段原话，来源及接口映射由技术提出。



## 六 其余题目与六域要求如何对齐

| 题目 | 需要解决的信息问题 | 建议 |
|---|---|---|
| R01 | 主要记录量表回忆时段 | 保留轻量表达；不要求写经历，不当作低质量短答 |
| R02 | 需要可定位的日常事件经过 | 优先加入可选经过提示 |
| R03 | 保留日期精度与不确定性 | 日期可更清楚，但允许不确定 |
| R05 | 交谈类别需要明确 | 先明确目标语义，再试细节提示 |
| R06 | 与R05关联的日期 | 保留真实选择和关联，不挪用到别的事件 |
| R08 | 同一期待需明确适用情境 | 增加适用情境；明确区分无期待和不愿说 |
| R09 | 需要本人具体行动 | 问清这次支持情境与本人具体动作 |
| R10 | 同一变化需前后与本人评价 | 选择变化或暂无变化，再补前后与评价 |
| R12 | 猜测不等于伴侣实际看法 | 保留为选答或后置，不充当核心材料来源 |

### Q05 期待要让用户说明何时适用

R08主问保留；愿意补充时再问“这种期待主要在什么情况下出现？”对象不清时问“主要希望谁或哪方面有什么变化？”用户确实没有具体期待时如实记录，不强行要求创造需要。双方共同固定情境下的期待比较，应标明是条件性期待，不包装成既往事实。

### Q06 支持题要取得具体行动

R09先明确用户想起哪次需要支持的情况，再问本人具体做法。允许“当时没有开口”等真实行动或明确未行动，不暗示正确答案是积极沟通。不把泛泛配合自动升级为具体行动。

### Q07 变化题给出完整但中性的结构

R10先让本人选择“能想到变化／目前没感到变化／不确定／不想回答”。有变化时，只围绕同一变化依次问之前、现在和本人怎样看待；评价可以正面、负面、复杂或没想清。明确暂无变化可按原规则处理，不默认勾选这个选项来补覆盖。

### Q08 核心内容不足时先控制负担

R12收的是猜测，建议后置或选答，先保证本人体验和行为的表达机会。暂不为了填满六域增加一整套量表，也不因D1资料少就恢复ISM18、临时补ECR-RS或改CSI题干。

本阶段并不要求六域全部足够。完整交付要求每人至少三个域足够，另有人体验、具体行为、自我变化及双来源实质内容等条件。应逐项采集对应信息，不能以“量表填满”代替这些条件。

开放题理解负担及答题量会影响回应；先降低每一步的任务量，再观察信息是否更充分。[R2] 使用认知访谈询问“这个词是什么意思、你怎么想起这件事、怎么选择答案”，比猜测用户敷衍更能定位原因。[R3]



## 七 怎样定义可用于验证的数据

### 三种判断分别记录

第一种是数据记录是否准确：系统有没有漏存、错配、混淆状态。第二种是报告是否可解释：能否定位原文，知道谁在何时说了什么，限制是否清楚。第三种是适合验证哪些规则：单方体验、共同事件或重复过程各需要不同材料。

一对没有近期分歧的认真用户，可以提供准确数据，却不适合验证共同冲突过程。全保密也可能是完全真实的选择。优质数据不能被定义为一定长、一定有冲突、双方一致，或一定得到完整结果。

### 两类真实资料分别用于不同问题

- 自然采集：面向实际或可能使用CORE的人，按统一流程尽力表达，保留全部合规完成、退出和资料不足情况，用于了解实际可采性。不能跑出abort就删掉。
- 定向规则验证：额外招募愿意分别描述近期普通互动的人，提前声明为覆盖特定分支而选取。验证重复过程时，需要本人愿意提供另一次不同的同类经历，不能让同一件事换说法充数。

两类可以有同一招募入口，但用途、筛选条件和统计分母须记录。自然采集的结果不能用定向挑出的正例替代；定向样本也不用于估计真实用户总体的成功率。

### 招募方式的优化方向

双方分别确认自己有了解关系或沟通方式的意愿，有适合独立作答的时间。朋友可以参与，但“帮团队完成任务”不应成为唯一筛选依据；非朋友也不天然认真。保留不同表达能力、关系阶段及常用设备。

先说明阶段一仅作内部规则测试，不承诺即时报告、心理诊断或一定形成共同结论。可以按投入时间提供固定补偿；补偿不与字数、严重事件、共同分析成功或取消保密挂钩。结束时可选填“尽力作答／有些题没理解／主要浏览／不便说明”，配合其他信号作解释，不单独作真实性鉴定。[R6][R7]

### 暂不采用的做法

不硬设每题几十字门槛，不强迫提供争吵，不按快速或同选项自动淘汰，不向伴侣转发私密线索，不为了提高通过率降低共同事件门槛，不用LLM补故事。语音、自由聊天、自动追问和多日日记可作为后续对照方案，本轮先检验低成本固定提示是否足够。



## 八 先验证什么再启动下一批

### 第一步 用控制用例验收系统

在新招募前确认：整页空白能够提醒且允许明确略过；中途关闭不会变成明确拒答；断网恢复不丢答；按钮原文准确归位；建对窗口一致；保密不被覆盖；固定量表题库逐项一致。先复用已有回归结果，仅补新增改动的检查。

### 第二步 做一轮小规模试采

建议先用2至3对目标特征相近、分别作答的人观察页面和题意。让每人先独立完成，再做简短回访，了解“如何理解题目、如何选择答案、如何理解保密、哪些提示有帮助”。这只是发现问题的早期工程试采，不能证明所有人都能理解或产品有效。[R1][R3]

不要让用户先做旧版再做新版的同一故事，用其第二次回答变长直接证明新版有效。若条件允许比较版本，以不同情侣分组、保持招募口径相近；小样本主要记录问题及方向，不作显著性或因果结论。

### 第三步 再进入目标用户采集

建议先取得3对自然完成的目标用户资料，逐对查看问题，再决定是否扩至6至10对。这个数量是节制投入的探索安排，不是统计样本量论证。不为凑够3个成功结果排除失败样本，也不在本次直接开始招募。

| 观察项 | 建议记录方式 | 怎么使用 |
|---|---|---|
| 整页无意漏答 | 观察＋事后自报＋页面记录 | 下一轮目标为不再出现未提示的整页遗漏 |
| CSI／PRI完整性 | 分人、分量表列已选数 | 区分主动缺答，不用自动补值提高 |
| 题意理解 | 本人复述词义及原因 | 反复误解则改题，不归罪用户 |
| 具体行为可定位 | 有合格来源的人数／适用人数 | 检查提示是否产生真实细节 |
| 期待及变化要素 | 各要素逐项人工记录 | 区分没有、不确定和未问出来 |
| 实质双来源比较 | 逐例列对象、来源、权限 | 至少出现真实合格实例后才称真实覆盖 |
| 重复过程 | 不同事件数及双方完整性 | 未出现就标未覆盖，不编正例 |
| 完成及退出 | 从邀请开始保留实际分母 | 评估负担，不能只看完成者 |
| 主动用时与体验 | 排除闲置并记录卡点 | 不预设统一最低时长 |
| 人工处理成本 | 每对处理时长和返工原因 | 防止新版把负担全转给标注 |

系统正确性、真人规则覆盖、用户是否受益分别评估。当前阶段先由团队检查内容是否有依据、可理解、可比较；向参与者提供结果及收集产品价值反馈须按后续阶段确认，不能提前发出尚未准许的报告。
